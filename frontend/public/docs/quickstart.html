Quickstart

Seven steps from an empty wallet to a settled withdrawal. You need a Base Sepolia EOA and, for the command-line steps, Foundry's cast — the app UI at perp.arcoralabs.xyz walks you through the same flow interactively and runs every check below for you.

Before you start

Everything below runs against Base Sepolia (chain ID 84532) with test funds only. RPC used in the commands: https://sepolia.base.org. Replace <YOU> with your address and <KEY> with its private key — use a throwaway testnet key, never a mainnet one. <VAULT> is the CollateralVault address: read it from vault on GET /v1/accounts/me (see the API reference), never from an old page or post. <USDC> is the vault's own token: cast call <VAULT> "token()(address)" --rpc-url https://sepolia.base.org.

1 Get Base Sepolia ETH

You need a little ETH for gas. Use a faucet, e.g. alchemy.com/faucets/base-sepolia.

2 Mint test USDC and approve the vault

The collateral token is an open-mint MockUSDC (6 decimals) — anyone can mint. This mints 1,000 USDC (1000000000 base units) to yourself and lets the vault pull it:

cast send <USDC> \
  "mint(address,uint256)" <YOU> 1000000000 \
  --rpc-url https://sepolia.base.org --private-key <KEY>

cast send <USDC> \
  "approve(address,uint256)" <VAULT> 1000000000 \
  --rpc-url https://sepolia.base.org --private-key <KEY>

3 Bind your address to the trading account

Open the app. The browser self-provisions a /v1 trading account for you (the API key is stored in your browser's localStorage). Bind the EOA you will deposit from — in the app, or via POST /v1/accounts/deposit/address. The binding is ownership-proven: you sign a message with the EOA's key. Withdrawals later pay this same address.

4 Get a deposit permit

The vault accepts only gateway-permitted deposits. Ask for a permit for the exact address and amount with POST /v1/accounts/deposit/authorize and {"from": "<YOU>", "amount": "1000000000", "marketId": 0, "purpose": "collateral"}. The reply carries three values:

  • ownerCommit — a blinded commitment to your trading account (32 bytes);
  • validUntil — the permit's expiry, in unix seconds;
  • sig — the gateway's 65-byte signature over the permit.

The permit is good for that one address and amount, until validUntil. The gateway refuses a permit while deposits are halted, when the exchange is in close-only mode, or when the amount exceeds the vault's remaining deposit capacity.

5 Deposit into the vault

Send the deposit with the permit's values before it expires. A dry run first (cast call) reports any refusal without spending gas:

# dry run: reverts with the vault's error selector if the deposit would fail
cast call <VAULT> \
  "deposit(uint256,bytes32,uint64,bytes)" \
  1000000000 <OWNER_COMMIT> <VALID_UNTIL> <SIG> \
  --from <YOU> --rpc-url https://sepolia.base.org

# deposit 1,000 USDC
cast send <VAULT> \
  "deposit(uint256,bytes32,uint64,bytes)" \
  1000000000 <OWNER_COMMIT> <VALID_UNTIL> <SIG> \
  --rpc-url https://sepolia.base.org --private-key <KEY>

What the vault's errors mean (error selector in brackets):

  • PermitExpired (0x1a15a3cc) — the block was past validUntil. Request a new permit (step 4); the old one can never land.
  • BondCapacityExceeded (0x0b9737f5) — the vault is at its deposit capacity, which the operator's bond sets. Try a smaller amount or later.
  • DepositsPaused (0xdeeb6943) or InCloseOnly (0xe087cf65) — the vault is not taking deposits.
  • BadAmount (0x749b5939) — the amount is zero or above the per-deposit limit.
  • OwnerCommitUsed (0x4e54eb54) — a deposit with this permit already landed. Do not send another.

Keep the deposit transaction hash. The finalized ingester credits the deposit to your trading account on its own once the block is finalized; POST /v1/accounts/deposit/onchain with {"txHash": "0x…", "marketId": 0} returns the durable credit receipt. While the receipt is pending, check again — do not send another deposit.

6 Trade

Place orders on the Trade tab. Order terms are sealed (encrypted) in your browser to the matching enclave's key — no plaintext terms travel on the wire. You get:

  • ACCEPTED — an enclave-signed receipt, within milliseconds;
  • MATCHED — a fill, also within milliseconds (soft finality);
  • SETTLED — when the window's zk proof is verified on-chain, roughly every 10–20 minutes.

MATCHED is not SETTLED — read the finality model before sizing positions.

7 Withdraw and claim

Withdraw on the Account tab. The app asks your wallet to sign the withdrawal (every withdrawal is wallet-signed — the API key alone cannot move funds), and the destination is your bound deposit address. The withdrawal goes through three visible stages:

  1. The withdrawal is recorded off-chain and shows as “Settling on-chain…” while it waits to be included in a settlement window.
  2. Once that window's proof settles, it becomes “Claimable” — the withdrawal is now a leaf in an on-chain Merkle root.
  3. Copy the cast command the UI builds for you and run it from any funded address — claims are permissionless, and funds can only ever go to the address bound into the leaf:
# exact arguments are generated by the app's Account tab
cast send <VAULT> \
  "claim(address,uint256,uint256,bytes32,bytes32[])" \
  <TO> <AMOUNT> <NONCE> <ROOT> <PROOF> \
  --rpc-url https://sepolia.base.org --private-key <ANY_FUNDED_KEY>

Each claim can execute once (AlreadyClaimed on replay), and any historically published root stays claimable — a later root can never strand your withdrawal.

If the exchange enters close-only mode

Close-only mode is permanent: the vault takes no new deposits, and from then on only the wind-down settles. A deposit that reached the vault but that settled state never credited is then refundable in full, straight from the vault. The refund needs no gateway and no operator.

  • The app lists such deposits under Refundable deposits on the Account tab, with a wallet button and a copyable command.
  • From the command line, take id from the vault's Deposit event in your deposit transaction's receipt (cast receipt <TX>); from, ownerCommit and amount are the values you deposited with.
# refund to the depositing address; anyone may send this
cast send <VAULT> \
  "refundDeposit(uint64,address,bytes32,uint256,address)" \
  <ID> <FROM> <OWNER_COMMIT> <AMOUNT> <FROM> \
  --rpc-url https://sepolia.base.org --private-key <ANY_FUNDED_KEY>

The vault checks the first four values against its own deposit record. The last argument is the recipient: anyone may send the refund to <FROM>, and only <FROM> itself may name another recipient. Each deposit refunds once (AlreadyRefunded). A deposit that settled state already credited is not refundable (NotRefundable): that balance leaves through the normal withdrawal and claim path.
