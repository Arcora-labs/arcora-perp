§0 · Tasarım tezi

Hız ve karanlık fiziksel olarak çekişir — üç ayrı güven kökü

Düşük latency'de gizliliği veren bileşen bir TEE'dir; ama TEE güveni yok etmez, başka köke taşır. Fairness, liveness ve recovery ayrı protokol yükümlülükleridir. Sistem bunu üç kökle dürüstçe ayırır:

Kritik incelik (§10): TEE kırılırsa vault'tan fon çalınamaz (ZK korur) — ama gizlilik, fair access, preconf güvenilirliği ve market integrity kırılabilir. Bu dürüstçe etiketlenir; enclave dokunulmaz bir kara kutu olarak sunulmaz.

§1 · Katman haritası

Sıcak yol (hot path): şifreli emir istemciden çıkar, TEE içinde operatöre kör eşleşir, attested prover soğukta ispatlar, Ethereum L1 hard-finalize eder; encrypted note archive kalıcı kurtarmayı besler.

Şekil 1 — hot path: client → TEE sequencer → attested prover → L1 settlement; oracle besler, note archive kurtarmayı kapatır

§3 · Finality semantics

Üç katmanlı finality, sistemin kalbidir. Arayüz MATCHED ≠ SETTLED ayrımını yanlış anlaşılmaz biçimde gösterir; bağlayıcı olan yalnızca SETTLED'dır.

ACCEPTED

Enclave emri aldı, seq_no + imzalı receipt verdi. İnclusion proof'un.

MATCHED

Fill preconfirmation imzalandı (soft). İyi niyetli, final değil, çekilemez.

SETTLED

ZK proof Ethereum'da verify oldu (hard). Bağlayıcı ve çekilebilir.

order_hash = H(encrypted_order, user_ephemeral_key, nonce, expiry, market_id)
receipt   = Sign_enclave(order_hash, seq_no, recv_time, batch_id_hint)

Failure matrisi (§3)

DurumSonuç
MATCHED + batch prove edildiNormal → SETTLED
MATCHED + batch prove edilemediBatch reddedilir; fill'ler rollback; insurance yalnızca kanıtlı protokol hatasında
MATCHED + enclave crashKullanıcı receipt + son hard root ile forced-exit (§6); SETTLED olmayan fill bağlayıcı değil
MATCHED var, L1 hard root yokWithdraw mümkün değil
Receipt var, MATCHED yok, timeout aşıldıInclusion ihlali → slashing + forced-exit

§2 · Sequencing accountability

ZK "bu batch içindeki state transition geçerli" der; "hangi emir hangi sırayla girdi, kim sansürlendi" demez. O boşluğu receipt + inclusion timeout + slashing kapatır. Her batch bir manifest yayınlar:

batch_manifest = {
  previous_state_root, batch_id,
  ordered_order_hashes[], rejected_order_hashes[] + reason_codes[],
  oracle_update_hashes[], matching_rule_version,
  enclave_measurement, sequencer_pubkey_epoch
}

Boşluk paylaşımı: ZK → manifest'teki sıralı emirler altında fill doğruluğu (Proof-v2). Receipt + timeout + slashing → "receipt aldım ama T blok içinde manifest'e girmedim" cezası. İkisi birlikte censorship/withholding'i kapatır.

§4 · Proof obligations — staged

Proof-v1 · invariant'lar Faz 0'da kodlandı

  • collateral conservation
  • valid nullifiers (double-spend yok)
  • fill sonrası margin yeterliliği
  • oracle freshness + confidence (§8)
  • funding formülü · liquidation threshold

Proof-v2 · matching determinism

  • committed log üzerinde deterministic price-time priority
  • cancel/replace ordering, self-trade prevention
  • partial fill, expiry, order tipleri (IOC/FOK/post-only/reduce-only)
  • likidasyon emir önceliği

v1'de matching doğruluğu receipt + manifest + slashing ile; v2'de kriptografik determinism ile garanti edilir.

§5–9 · Risk · likidasyon · forced-exit · recovery · oracle

Likidasyon (§5)

Enclave plaintext pozisyonları public oracle'a karşı sürekli değerlendirir → anında tetikler. Liveness varsayımı yok: kullanıcı offline olsa da likide edilir. Public'e per-position açıklama yok; yalnızca aggregate + ZK proof.

Forced-exit (§6)

Sequencer T blok yanıt vermezse kullanıcı son hard root'a karşı forced action başlatır → sistem CLOSE-ONLY moduna girer → açık perp'ler conservative oracle TWAP'a karşı kapanır. Açık pozisyon collateral'ı kapatılmadan çekilemez.

Note recovery (§7)

4844 blob'ları geçici. Encrypted Note Archive zorunlu: public ciphertext arşivi, view-key ile taranır (batch_id → note_commitment → ciphertext). Cihaz kaybında: seed → view-key → arşivi tara → pozisyonu yeniden kur.

Oracle (§8)

Transcript: signed_price, publish_time, confidence, max_staleness, max_deviation_vs_backup. ZK doğrular: zamanda; confidence ≤ threshold; |primary − backup_twap| ≤ sanity. Pyth-primary + TWAP backup + anomalide close-only breaker.

Confidential proving boundary (§10b): ZK witness'ı verifier'dan gizler, prover'dan değil. Çıplak prover farm her fill'i plaintext görür → prover çıplak sunucu olamaz. v1: attested prover (TDX/Nitro), witness yalnızca attested measurement'ta açılır, job bitince silinir. Private batch'i public proving network ile üretemezsin.
