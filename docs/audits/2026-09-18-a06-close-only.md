# A06 — CloseOnly counterparty-free exit remediation

Base: merged A05 main `83a661c08f4a0db7d1e321af50a6053b645dd192`.

The previous CloseOnly design could strand a healthy open position forever because every
ordinary close was a two-sided fill and CloseOnly forbids the counterparty from opening new
exposure. A06 adds a proof-bound two-phase wind-down.

Phase 1 is exactly one `SettleAll`. It has no price input: every open position closes at its
own entry price, so unrealized PnL is deliberately voided as an emergency bankruptcy policy.
Committed funding is settled. Pre-existing negative collateral and a negative clearing pool
are normalized using insurance and treasury first, then a deterministic global pro-rata
haircut over positive position collateral and live notes. The whole transition is staged and
commits only after all checked arithmetic, note uniqueness/capacity and solvency checks pass.

Phase 2 has distinct `WindDownUnbind` and `WindDownWithdraw` operations. They require proven
CloseOnly state; unbind is flat-position-only and oracle-free. The circuit derives phase from
the op grammar. Mixed phase/ordinary batches are rejected before mutation.

Normal seven-root commitments are unchanged. Phase 1/2 append a little-endian phase word.
Solidity has a separate `windDownCommitment`; `settleBatch` remains phase 0, one-shot
`finalSettle` requires phase 1, and repeatable `finalExit` requires phase 2 after phase 1.
This prevents a witness from placing SettleAll in an ordinary batch and using the normal L1
entrypoint.

The gateway admin trigger is FIN_ADMIN_KEY gated, checks L1 close-only at one named block,
requires durable persistence/prover configuration and an empty ordinary window, previews the
transition, archives any replacement haircut notes for registered owners, applies SettleAll,
waits for snapshot ACK, then forces the settle loop. CloseOnly account withdrawals use the
price-free phase-2 ops. The L1 bridge routes by the locally derived phase, not by a prover
response field.

Local verification in this remediation includes dedicated A06 core tests, Rust/Solidity
phase-1 commitment KAT, L1 phase routing test, Clippy `-D warnings`, rustfmt, core/matcher
no_std builds, and the full Foundry suite. The full workspace suite was attempted locally but
the existing note-archive fuzz target exceeded the workspace wall-clock budget; it had
already reached the gateway suite with 323 passed / 1 ignored and matcher suites clean.
GitHub PR CI is therefore required before merge and is the authoritative full-workspace run.

Not performed locally: real SP1 proof, guest ELF/vkey regeneration, live TEE, live L1
transaction, deployment, or physical failure testing. Because the guest program changes,
A11 must rebuild/re-pin the real SP1 program vkey and verify the deployed verifier/binary
pair before real-value use.
