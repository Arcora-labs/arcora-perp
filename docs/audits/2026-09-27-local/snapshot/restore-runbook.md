# Local restore drill and reconciliation boundary

Only disposable synthetic state was used. The successful atomic write test verifies private file permissions, authenticated read-back, and exact reserialization. Oversized write/read, missing-parent, and rename-over-directory cases verify explicit failure and preservation/cleanup. `crash-drill-matrix.json` separately lists the process-kill, fsync-injection and physical-power cases **not run**. This is partial S6-02 evidence, not a complete durability certification.

For a suspect deployment snapshot: stop mutations through the established incident procedure; retain the snapshot and its `.rollback` companion, collect hashes on copies, identify matching source/version and securely retained seed, and inspect the durable chain checkpoint. Never delete a snapshot/journal or reset recovery generations to obtain a fresh boot. Open/authenticate a copy under its correct seed and version, validate A01 routing/prefix, native root/nullifiers/unspent notes/withdrawals and authorizer generations, then reconcile the rollback journal's prepared window against the chain. If version, checkpoint or key continuity is unknown, remain halted and report the outcome as unknown. This runbook was written from the local source/test evidence; no independent operator performed the full deployment procedure.

The `crates/gateway/testdata/snapshots/v5` through `v8` fixtures are public synthetic examples, not live backups. Their complete SHA-256 inventory is `fixture-sha256.txt`. They can be replayed with `cargo test --locked -p gateway s3_historical_writers_preserve_state_authority_and_replay -- --nocapture`; expected selection is one test running four versions. The full finite parser campaign is `cargo test --locked -p gateway s3_ -- --nocapture --test-threads=1` (eight selected tests in this source revision).

Fixture generation rebuilds actual historic commits using `generate-historical-fixtures.py`; it requires Cargo dependencies and must be explicitly chosen because the synthetic accounts/nonces are fresh each generation and would change frozen hashes. The generator touches archive file **metadata only** before compilation. This is necessary because `git archive` retains historical mtimes and a reused Cargo target otherwise can silently borrow workspace artifacts from another source tree. Invalidated attempts are retained under `stale-cache-attempt-*`; they are not counted as successful historical-source evidence.
