## Verified constraints

- `chainlink-oracle/src/binding.rs` already defines `DPCLK3`, `CandidateWitness`, ordered `PairEvidence`, `check_evidence`, and `run_encoded`. Every oracle-bearing op has exactly one evidence pair, at its original operation time. Maximum evidence count is 128; wire size is bounded at 16 MiB.
- A3 `gateway/src/price_lifecycle_tests.rs::candidate` builds a genuine gateway window into that witness using exact archive IDs. Its exporter writes actual normal/liquidation witnesses and negative cases for native/CPU parity. It exports body evidence, rather than the full report registration payload.
- Candidate guest v3 intentionally uses the existing **v2 inner clock**: `ClockBoundVerifier.proofVersion()==2`, its v2 receipt/domain, and the `ClockContext`. Changing the clock to version 3 would break the existing candidate. `DPCLK3`, `DPCAS3`, and journal v6 are different format/version domains.
- `ChainlinkOracleVerifier.register` binds two different hashes. `inputHash = keccak256(abi.encode(Entry[]))` covers the exact full report bytes, including signature containers, and controls exact retries/replacement. `evidenceHash` covers ordered `(marketId, nowMs, keccak(baseBody), keccak(quoteBody))` and is reproduced by the guest. Neither may replace the other. Archive IDs are host provenance; they are not extra candidate public-input fields.
- The proof commitment binds clock commitment, wrapper address, streams proxy address, policy hash and evidence hash. Policy hash alone omits wrapper/proxy addresses; archive `policy_binding` additionally binds them.
- Uptime feed/grace are immutable wrapper identity. The registered `(roundId, startedAt)` epoch is wrapper state, not a witness field. For priced batches both current time and original first-operation seconds must be strictly after grace; registration/settlement must stay in the same healthy epoch. Empty price-free evidence uses the existing zero-epoch path.
- Existing `main.rs::ensure_submission_supported` and `clock_client.rs::ensure_resume_supported` reject candidate submission and exact v2 resume, including zero-oracle batches. Preserve both.
- The current prover-service builds the reviewed `sp1-guest`; `PublicInputs`, sealed derivation and `/prove` are legacy/DPCLK2. `/vkey` reports a key but the prove response has no candidate protocol/ELF/key identity. Existing `PreparedSettle`/v6 WAL do not represent candidate clock/report/uptime stages. Do not send DPCLK3 through this service or old preparation path.

## Smallest independently reviewable implementation

Add an **offline, test-only candidate protocol module** and its tests. It has no L1/HTTP implementations, environment activation or conversion into live `PreparedSettle`. Keep all production blockers. Reuse A3's actual lifecycle fixture within its test scope rather than substituting invented fills.

Suggested files/interfaces:

1. `gateway/src/report_archive_binding.rs`: `candidate_material(ops, authenticated_envelope) -> CandidateMaterial`. Verify canonical refs equal the supplied exact refs, policy, original times and every selected immutable record. Return a pinned policy, ordered `PairEvidence`, original full-report `RegistrationEntry` bytes, and IDs. Never search by price or select a sibling.
2. New `gateway/src/candidate_protocol.rs`: pure `preflight(...) -> CandidatePlan`, `attach_clock(plan, context) -> CandidateRequest`, and `check_response(request, response) -> HarnessPreparedCandidate`. Explicit identity contains candidate protocol tag, SDK, ELF SHA and vkey. Explicit target contains chain/network, settlement, clock, wrapper/proxy, policy binding/hash, uptime feed/grace and local runtime identities. Preflight checks topology, program identity, archive material, native transition/withdrawal roots, timing bounds, policy coverage, 128 entries and wire bounds **before any callback**. Attach validates the exact returned clock and emits canonical DPCLK3 bytes; expected public output comes from native `run_encoded`.
3. New `candidate_protocol_tests.rs`, included in the A3 fixture's test scope: a private `HarnessTransport` with counted `register_clock`, `register_reports`, `prove_candidate`, and `broadcast_candidate` callbacks. Only owned synthetic mocks implement it. Response must repeat exact protocol/program identity and expected 32-byte public commitment; roots come from local replay. A mock commitment proof is explicitly labelled and cannot attest cryptographic program execution.
4. A separate, bounded `HarnessCandidateIntent` DTO in an owned temporary file records protocol/target, exact immutable witness/material hashes, clock receipt, report input/evidence hashes, uptime epoch and stage before callbacks. Re-read it for simulated crash recovery. Do not extend or reinterpret production v6 `PreparedSettle` in this first package. A future live candidate WAL needs its own explicit version and boot handling.
5. Optional paired `contracts/test/ChainlinkCandidateProtocol.t.sol` consumes public synthetic registration vectors and checks native/body/full-ABI hash parity using the real clock/oracle/settlement wrappers with mock DON/SP1/uptime. Existing contract tests already exercise these wrappers. A full exact host-to-contract witness bridge is a separate local integration step; a Rust spy alone must not be reported as that bridge.

The harness order is: preflight → durable candidate intent → exact clock registration/observation → ordered full-report registration/observation → candidate-only proving → durable prepared result → exact target/receipt/report/epoch recheck → mock broadcast. Ambiguous callbacks retain the same intent and forbid changed timestamps/payloads.

## Acceptance gates

- Positive actual A3 normal and liquidation windows: identical op order/times/IDs; exact full report payloads; native DPCLK3 commitment; selected candidate identity; expected mock call sequence. Price-free candidate case stays candidate and handles the existing empty-evidence uptime exception only inside the harness.
- Known wrong version/guest/SDK/ELF/vkey, chain/network/target/topology/policy, missing/corrupt selected archive, substituted equal-body sibling, reordered/dropped/extra evidence and capacity/wire violations: all four callback counters remain zero.
- Changed clock receipt/roots/bounds after clock registration: no report registration, prove or broadcast. Report/DON body mismatch or failed report observation: no prove/broadcast. Bad prover commitment/key response: no broadcast. These late failures cannot truthfully claim zero already-attempted earlier callbacks.
- Uptime down/unknown/grace rejects priced preflight; a changed round or startedAt after registration rejects reuse/broadcast. Report expiry after an already verified exact registration is not permission to refresh sources. Exact retry preserves full ABI input hash, receipt and epoch.
- Failed intent/prepared persistence: no subsequent callback; old bytes and recovery inputs survive. Restart reuses the same identity/material and rejects v2/candidate cross-resume. Production submission/resume blocker tests remain green.
