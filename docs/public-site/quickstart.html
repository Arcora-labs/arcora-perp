Quickstart

Six steps from an empty wallet to a settled withdrawal. You need a Base Sepolia EOA and, for the command-line steps, Foundry's cast — the app UI at perp.arcoralabs.xyz walks you through the same flow interactively.

Before you start

Everything below runs against Base Sepolia (chain ID 84532) with test funds only. RPC used in the commands: https://sepolia.base.org. Replace <YOU> with your address and <KEY> with its private key — use a throwaway testnet key, never a mainnet one.

1 Get Base Sepolia ETH

You need a little ETH for gas. Use a faucet, e.g. alchemy.com/faucets/base-sepolia.

2 Mint test USDC

The collateral token is an open-mint MockUSDC (6 decimals) — anyone can mint. This mints 1,000 USDC (1000000000 base units) to yourself:

cast send 0x9F5365c947eCaBaf62f42EF0Fe92ab909f709bDA \
  "mint(address,uint256)" <YOU> 1000000000 \
  --rpc-url https://sepolia.base.org --private-key <KEY>

3 Approve and deposit into the vault

Collateral is custodied by the CollateralVault. Approve it, then deposit:

# approve the vault to pull your USDC
cast send 0x9F5365c947eCaBaf62f42EF0Fe92ab909f709bDA \
  "approve(address,uint256)" 0xC3EBc0f7301D5a914b01b8d2a1B5574764330c05 1000000000 \
  --rpc-url https://sepolia.base.org --private-key <KEY>

# deposit 1,000 USDC
cast send 0xC3EBc0f7301D5a914b01b8d2a1B5574764330c05 \
  "deposit(uint256)" 1000000000 \
  --rpc-url https://sepolia.base.org --private-key <KEY>

Keep the deposit transaction hash — you need it in the next step.

4 Bind your address and credit the deposit

Open the app. The browser self-provisions a /v1 trading account for you (the API key is stored in your browser's localStorage). To credit the on-chain deposit to that account:

  1. Bind the EOA you deposited from — in the app's API tab, or via POST /v1/accounts/deposit/address. The binding is ownership-proven: you sign a message with the EOA's key.
  2. Credit the deposit by transaction hash — via POST /v1/accounts/deposit/onchain with {"txHash": "0x…", "marketId": 0}. The gateway verifies the transaction on-chain and credits your trading balance.

Request and signature details for both endpoints are in the API reference.

5 Trade

Place orders on the Trade tab. Order terms are sealed (encrypted) in your browser to the matching enclave's key — no plaintext terms travel on the wire. You get:

  • ACCEPTED — an enclave-signed receipt, within milliseconds;
  • MATCHED — a fill, also within milliseconds (soft finality);
  • SETTLED — when the window's zk proof is verified on-chain, roughly every 10–20 minutes.

MATCHED is not SETTLED — read the finality model before sizing positions.

6 Withdraw and claim

Withdraw on the Account tab. The app asks your wallet to sign the withdrawal (every withdrawal is wallet-signed — the API key alone cannot move funds), and the destination is your bound deposit address. The withdrawal goes through three visible stages:

  1. The withdrawal is recorded off-chain and shows as “Settling on-chain…” while it waits to be included in a settlement window.
  2. Once that window's proof settles, it becomes “Claimable” — the withdrawal is now a leaf in an on-chain Merkle root.
  3. Copy the cast command the UI builds for you and run it from any funded address — claims are permissionless, and funds can only ever go to the address bound into the leaf:
# exact arguments are generated by the app's Account tab
cast send 0xC3EBc0f7301D5a914b01b8d2a1B5574764330c05 \
  "claim(address,uint256,uint256,bytes32,bytes32[])" \
  <TO> <AMOUNT> <NONCE> <ROOT> <PROOF> \
  --rpc-url https://sepolia.base.org --private-key <ANY_FUNDED_KEY>

Each claim can execute once (AlreadyClaimed on replay), and any historically published root stays claimable — a later root can never strand your withdrawal.
