API Reference

The gateway exposes a JSON HTTP API under /v1, served from the app origin https://perp.arcoralabs.xyz. A machine-readable spec is available at GET /v1/openapi.json.

Conventions

  • Auth: pass your API key in the X-Api-Key header. Get one from POST /v1/accounts.
  • Amounts are decimal strings of scaled integers: quote (USDC) amounts are scaled by 1e6, sizes and prices by 1e8. Example: 1,000 USDC = "1000000000"; 0.5 BTC = "50000000".
  • Rate limit: order placement is limited to 10 orders/second per account; excess returns 429.
  • Sealed ingress: in production posture, POST /v1/orders refuses plaintext order terms — orders must arrive sealed to the enclave's epoch key. See the wire format below.

Accounts

POST/v1/accounts

Register a trading account. Returns {apiKey, owner, callerSigned} — the API key authenticates all further calls; owner is the account's 32-byte owner public key (the value sealed-order AAD binds to). Optionally pass {"signer": "0x…"} to register in caller-signed mode, where each order additionally carries a 65-byte secp256k1 signature over the order hash made with your own key.

GET/v1/accounts/me

Your account: balance, positions, and nextNonce (the nonce your next sealed order must carry).

POST/v1/accounts/deposit/address

Bind the external EOA you fund USDC from. Body: {"address": "0x…", "signature": "0x…"}. The binding is ownership-proven: signature is a 65-byte r‖s‖v secp256k1 signature (v ∈ {27, 28}) made with the deposit EOA's key over this digest:

digest = keccak256(
    "dark-perp:bind-deposit:"  // fixed ASCII prefix (23 bytes)
 ‖ owner            (32)      // your account owner, from POST /v1/accounts
 ‖ depositAddress   (20)      // the EOA being bound
)

The ASCII prefix "dark-perp:bind-deposit:" is a fixed protocol identifier — use it verbatim. Sign the raw 32-byte digest directly (no EIP-191 "\x19Ethereum Signed Message" prefix); the signature must recover to the address being bound. Binding the account owner into the digest means the proof cannot be replayed to bind your address to someone else's account, and an address can be bound to at most one account. The app's API tab produces this signature for you.

POST/v1/accounts/deposit/onchain

Credit a real on-chain vault deposit to your trading account. Body: {"txHash": "0x…", "marketId": 0}. The gateway verifies the transaction on-chain (it must be a vault deposit from your bound address) and credits your balance.

POST/v1/accounts/withdraw

Record an authorized withdrawal. Body: {"marketId": 0, "amount": "1000000000", "to": "0x…"}. The withdrawal enters the current settlement window; once that window settles, it is claimable on-chain. See what is withdrawable, when.

GET/v1/accounts/withdrawals

Your withdrawals with their status and Merkle claim proofs — everything needed to call claim(to, amount, nonce, root, proof) on the vault.

Orders

POST/v1/orders

Place an order. Sealed body: {"epochId": <n>, "sealed": "0x…"} (see wire format). Returns an enclave-signed receipt — store it; it is your inclusion evidence in the on-chain challenge game. Responses: 200 signed receipt, 400 rejected, 429 rate-limited (10/s per account).

GET/v1/orders

Your orders with their finality state (ACCEPTED / MATCHED / SETTLED).

DELETE/v1/orders/:orderId

Cancel a resting (ACCEPTED) order.

GET/v1/positions

Your open positions.

Market data

GET/v1/markets  ·  GET/v1/markets/:id

All markets, or one market (id = 0 BTC, 1 ETH, 2 SOL). Public, no auth.

GET/v1/markets/:id/orderbook

Aggregate order book depth. Public — per-account balances and positions are never visible here.

GET/v1/markets/:id/candles?tf=15m&limit=120

Price history (engine marks; exchange-backfilled for feed markets). tf ∈ 1m, 5m, 15m, 1h, 4h, 1d (default 15m); limit up to 240 (default 120). Returns candles[] of {t, o, h, l, c} with 1e8-scaled string prices.

GET/v1/markets/:id/oracle

The current validated oracle price for the market.

LP pool

GET/v1/lp  ·  POST/v1/lp/deposit  ·  POST/v1/lp/withdraw

The house market maker's equity pool. GET /v1/lp returns the pool's stats and your own stake. Stake with POST /v1/lp/deposit, body {"amount": "1000000000"} (USDC, 1e6-scaled string) → {"sharesMinted"}; unstake with POST /v1/lp/withdraw, body {"shares": "…"} → {"withdrawnValue"}. All three are authenticated.

System

GET/v1/system/status

System status, including settlement-window progress you can compare against the on-chain batch count.

GET/v1/batch/:id

Settlement status of a window: {windowId, settled}.

GET/v1/enclave/epoch

The enclave's current order-ingress key: {epochId, x25519Pub, notAfterMs, measurement, sig}, signed by the enclave's secp256k1 identity. Verify before sealing — see below.

WS/v1/ws

WebSocket: public live-market snapshots every tick. After sending {"type": "auth", "apiKey": "0x…"}, you also receive your own account events — fills, order finality transitions, ADL haircuts.

Sealed order wire format (for bot authors)

Order terms never travel in plaintext: the client serializes them to a canonical 51-byte layout, encrypts (“seals”) them to the enclave's rotating X25519 epoch key, and POSTs only {epochId, sealed}. The reference implementation lives in the repository at frontend/src/api/sealedBox.ts (the sealed-box primitive) and frontend/src/api/realClient.ts (epoch verification, serialization, and the full submit flow) — both pinned byte-for-byte against the Rust side by cross-language test vectors.

Step 1 — fetch and verify the epoch key

GET /v1/enclave/epoch returns {epochId, x25519Pub, notAfterMs, measurement, sig}. Before sealing anything, verify the signature — fail closed on any mismatch:

digest = keccak256(
    0x19                       // domain tag byte 25
 ‖ epochId  as u64 LE (8)
 ‖ x25519Pub        (32)
 ‖ notAfterMs as u64 LE (8)
)                              // 49-byte preimage

sig is a 65-byte r‖s‖v secp256k1 signature (v ∈ {27, 28}). Recover the public key from digest and require its Ethereum address to equal the enclave signer 0x92173839C6B3b717179ba5505CCE31bD2131EbA0. notAfterMs is an advisory expiry — refetch the epoch once it passes.

Step 2 — serialize the order terms (51 bytes, all little-endian)

OffsetFieldTypeBytesNotes
0marketIdu64 LE80 = BTC, 1 = ETH, 2 = SOL
8sideu811 = Buy, 2 = Sell
9sizei128 LE161e8 scale; must be > 0
25limitPricei128 LE161e8 scale; 0 = market order
41tifu811 = GTC, 2 = IOC, 3 = FOK, 4 = PostOnly
42reduceOnlyu810 = false, 1 = true
43nonceu64 LE8strictly increasing per account

The nonce must strictly increase per account — fetch the expected value as nextNonce from GET /v1/accounts/me. A captured {epochId, sealed} body that is re-POSTed is rejected.

Step 3 — seal to the verified epoch key

The sealed box is X25519 ECDH → HKDF-SHA256 → XChaCha20-Poly1305:

  1. Generate an ephemeral X25519 keypair (esk, epk) and a random 24-byte nonce.
  2. Compute the shared secret: X25519(esk, x25519Pub).
  3. Derive the AEAD key: HKDF-SHA256(ikm = shared, salt = epk ‖ x25519Pub, info = "arcora/sealed-box/v1") → 32 bytes.
  4. Build the AAD, binding the ciphertext to this epoch and your account (no cross-account replay): 
    aad = 0x1C                     // domain tag byte 28
   ‖ epochId as u64 LE (8)
   ‖ owner           (32)     // from POST /v1/accounts
  5. Encrypt the 51-byte terms with XChaCha20-Poly1305 under that key, nonce, and AAD.

The wire format is version byte 0x01, then the ephemeral public key, nonce, and ciphertext with its tag:

sealed = 0x01 ‖ epk(32) ‖ nonce(24) ‖ ciphertext‖tag
       // 51-byte plaintext → 1 + 32 + 24 + 51 + 16 = 124 bytes

Step 4 — submit

POST /v1/orders
X-Api-Key: <your api key>
Content-Type: application/json

{"epochId": 3, "sealed": "0x01…"}

The response is an enclave-signed receipt. Keep it: it proves your order was accepted, and it is the evidence you would use in the on-chain inclusion challenge if a settled window ever omitted your order.
