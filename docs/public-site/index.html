Arcora Perp

A privacy-preserving perpetual futures DEX, running as an application-specific rollup. Orders are matched inside a hardware enclave in milliseconds; every settled state transition is re-executed inside a zkVM and proven on-chain.

Testnet alpha

Arcora Perp is live as a public testnet alpha on Base Sepolia at perp.arcoralabs.xyz. All funds are test funds (open-mint MockUSDC). The system has known limitations and no third-party audit — read the trust model before forming expectations.

What it is

Arcora Perp trades BTC, ETH, and SOL perpetual futures on a price-time-priority central limit order book, collateralized in USDC. Two things distinguish it from a typical DEX:

  • Privacy. Order terms are encrypted in your browser to the matching enclave's key — the HTTP request carries no plaintext trade terms. Account balances and positions live as encrypted notes; the public sees aggregate book depth, not your account.
  • Proven settlement. The operator cannot simply assert a new state. Every settlement window is re-executed inside an SP1 zkVM — fills, funding, liquidations, ADL, deposits, withdrawals — and the resulting Groth16 proof is verified by a contract on Base Sepolia before the state root advances.

The TEE + zk hybrid, in one pass

A TEE gives speed and privacy; a zk proof gives verifiability. Arcora Perp chains them:

1

Match in a TEE milliseconds

The order book and sequencer run inside an Intel TDX confidential VM. The enclave identity is attestation-bound (DCAP quote, measurement pinned at boot).

2

Sign a receipt milliseconds

Every accepted order returns an enclave-signed receipt — soft finality, and your evidence in the on-chain challenge game if the operator ever drops your order.

3

Prove the window ~10–20 min

Activity is sealed into windows. An SP1 zkVM proof re-executes the entire engine transition from the previous state root to the new one; the proof is wrapped into Groth16.

4

Verify on-chain hard finality

The settlement contract on Base Sepolia verifies the proof and enforces state-root continuity. Withdrawals become permissionless Merkle claims against the vault.

TEE provides

  • Millisecond matching
  • Order & balance privacy
  • Attested enclave identity
  • Signed inclusion receipts

zk proof provides

  • Unforgeable state transitions
  • No inflated balances or fake fills
  • All commitment roots derived in-proof
  • Trustless Merkle withdrawals

Chain provides

  • USDC custody in the vault
  • Proof verification per window
  • Challenge game + operator bond
  • Forced exit on liveness failure

The full pipeline — windows, the challenge game, the privacy layer, crash recovery — is on the Architecture page.
